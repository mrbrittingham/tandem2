# Tandem agent instructions

Use these constraints when editing this monorepo.

## Branch safety rules (hard requirements)
- Before editing any file, print current branch (`git branch --show-current`).
- `main` is the default production branch and valid for normal edits/deploy work.
- Do not auto-switch branches. Use a feature branch only when explicitly requested (for example large/unsafe changes).
- After edits, commit to the branch requested for the task.
- Always end with a release summary that includes:
	- current branch
	- commit hash
	- files changed
	- whether a migration was added
	- verification commands run
	- next deployment steps
- If any migration file was added in `supabase/migrations/`, explicitly state: `needs Supabase migration applied`.

## Current architecture (source of truth)
- npm workspaces monorepo with:
	- `apps/dashboard` (operator console, port 3100)
	- `packages/ui-kit` (embeddable `ChatWidget` and widget presentation)
	- `packages/shared` (types, mock store, LLM/storage server utilities)
- Backend API logic must stay in Next.js App Router route handlers (`src/app/api/**`).
- Do not introduce new standalone servers or alternate runtimes; the existing website-import worker (`scripts/worker/website-import-worker.ts`) is the approved async exception.

## Dashboard navigation (current)
The console has four top-level routes:
- `/overview` (Home) — AI-oriented read-only overview panels + quick prompt chips
- `/conversations` — chat history viewer
- `/chatbot` — unified 4-tab chatbot config (Knowledge | Handoff | Behavior | Appearance)
- `/account` — business identity, integrations, team/billing stubs

The `/chatbot` page tabs back to `/knowledge`, `/handoff`, `/intents`, `/widget` as full editors.
There is no `BusinessSubNav`. The old per-section sub-nav was removed in pass 5.

## DO NOT MODIFY — protected routes
These routes are production-critical. Do not edit them without explicit instruction:
- `apps/dashboard/src/app/api/operator-chat/route.ts`
- `apps/dashboard/src/app/api/operator-chat/confirm/route.ts`

`/api/operator-chat/confirm` enforces auth, business membership check, and schema validation before any write. Altering its guards is a security risk.

## Repository intent to preserve
- Tandem is restaurant-centric first, not generic FAQ tooling.
- Website import flow is classification-first, then extraction and review/apply.
- Prefer structured restaurant knowledge (events/menu/reservations/memberships) over FAQ-first logic when structured data is present.
- Chat responses should prioritize imported structured knowledge before generic assumptions.

## High-value patterns to preserve
- Dashboard state is mock-first and browser-persistent:
	- `packages/shared/src/mock-store.ts` stores state in `localStorage` key `tandem:mock-state`.
	- `apps/dashboard/src/lib/store-hooks.ts` consumes it via `useSyncExternalStore`.
- `apps/dashboard/src/lib/config-store.ts` provides a `configVersion` signal; pages re-fetch location config when the version increments (triggered after confirmed operator AI writes).
- Widget config is derived from business records using `businessToWidgetConfig(...)`.
- `ChatWidget` flow is API-mediated:
	- Hydrates with `GET /api/chat`
	- Streams with `POST /api/chat`
	- Keeps session continuity via `tandem_session` cookie.
- Chat route behavior lives in `apps/dashboard/src/app/api/chat/route.ts` and shared handlers in `packages/shared/src/server/chat-handler.ts`.
- Operator AI tool-calling uses `AISidebarContext` to pre-fill sidebar prompts from Overview page prompt chips.

## Shared package boundaries
- Client-safe imports use `@tandem/shared`.
- Server-only imports use `@tandem/shared/server` (route handlers/server contexts only).
- Prefer reusable domain logic in `packages/shared` and reusable presentation logic in `packages/ui-kit`.

## Architecture and schema guardrails
- Do not fabricate architecture details, routes, providers, or data flow behavior.
- Do not invent database tables, columns, or RPC signatures.
- Before DB-related edits, verify facts in `supabase/migrations/*` and `docs/DATABASE_SCHEMA.md`.
- Before major flow edits, verify current behavior in `docs/architecture.md` and relevant route/lib files.

## Context loading discipline
- Load context in this order before broad code exploration:
	1. `AGENTS.md`
	2. `docs/architecture.md`
	3. `docs/REPO_INDEX.md`
	4. only then the relevant module files for the task
- Start with focused reads instead of broad repo scans.
- Use `docs/REPO_INDEX.md` to jump directly to relevant modules.
- Scan widely only when local context is insufficient.

## Integration details
- LLM provider is env-driven in `packages/shared/src/llm/client.ts`:
	- `LLM_PROVIDER` defaults to `openai`
	- `LLM_MODEL` defaults to `gpt-4o`
	- `OPENAI_API_KEY` required for OpenAI
	- Anthropic/Google providers currently throw “not implemented”
- Supabase auth/dashboard flows require:
	- `NEXT_PUBLIC_SUPABASE_URL`
	- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- Chat persistence uses `getChatStore()`:
	- File-backed storage in `.data/` at repo root by default
	- Override with `TANDEM_DATA_DIR`
	- Falls back to in-memory store on file-store init failure
- Supabase migrations are operationally sourced from `supabase/migrations/*`.
	- Do not add new production migrations only under `packages/shared/supabase/migrations/*`.
	- Run `npm run guard:migrations` before `supabase db push`.
	- Reconciliation reference: `docs/migration-reconciliation.md`.

## Scope contract (stabilization)
- Canonical scope for chat + conversations is always `businessId + locationSlug`.
- Keep this pair consistent across widget requests, `/api/chat` (GET/POST), `/api/conversations`, and `/api/conversations/[sessionId]`.
- Legacy fallback paths may remain temporarily, but fallback usage should be visible in non-production logs.

## Project conventions
- In UI/API flows, `business.slug` is commonly used as `businessId`.
- For streaming chat routes, keep `export const runtime = "nodejs"`.
- Prefer `NextResponse.json(...)` for JSON APIs and consistent error shape `{ error: string }`.

## Developer workflow
- Install deps from root: `npm install`
- Dashboard loop: `npm run dev`, `npm run lint`, `npm run typecheck`, `npm run build`
- Clean stale Next/Turbopack artifacts: `npm run clean`
- Supabase migration push: `supabase db push` (after linking project)
- No automated test suite currently; validate with typecheck/lint and targeted route/page verification.
