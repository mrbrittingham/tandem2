## SUMMARY

Pass 4 replaces the analytics-focused overview page with a read-only chatbot
state surface. The operator can now see the health of their chatbot configuration
at a glance, interact with panels that summarise each domain (hours, knowledge,
behavior, handoff), view a live widget preview, and trigger AI sidebar prompts
via inline prompt chips — all without navigating away from the overview.

Key design decisions:
- Two-column layout: left = state panels, right = sticky widget preview
- No mutation on the overview page itself; all changes go through the AI sidebar
- Prompt chips call prefillInput() to stage the command in the sidebar without autosending
- useConfigStoreVersion() drives a re-fetch of recent conversations whenever the AI
  sidebar confirms a write operation
- AISidebarContext uses a ref-backed subscriber pattern so the overview cannot
  accidentally hold stale closures

## FILES CREATED

apps/dashboard/src/contexts/AISidebarContext.tsx
  Pub/sub context that lets any page component pre-fill the ConsoleSidebar chat
  input.  Exports: AISidebarProvider, useAISidebar (with prefillInput /
  registerPrefill).  Uses useRef<(text: string) => void | null> so the sidebar
  always receives the latest setter without the provider re-rendering.

apps/dashboard/src/components/console/panels/HealthSummaryBar.tsx
  Three inline status badges shown in the page header: Hours, Knowledge, Handoff.
  Each badge is emerald (configured) or orange (needs attention) based on whether
  the relevant slice of the location profile is populated.

apps/dashboard/src/components/console/panels/HoursPanel.tsx
  Displays operating hours blocks with day-grouping (consecutive days with the
  same open/close pair are collapsed to a range), formatted 12-hour time labels,
  and an "Update my hours" prompt chip.  Shows a warning empty state when no
  hours are configured.

apps/dashboard/src/components/console/panels/KnowledgePanel.tsx
  Shows total FAQ count, the first three FAQs as expandable accordion rows, a
  link to the full Knowledge page, and two prompt chips: "Add a Q&A" and
  "Remove a Q&A".

apps/dashboard/src/components/console/panels/BehaviorPanel.tsx
  Renders toneVoice, shouldAnswer topics, shouldAvoid topics, and conversionGoals
  derived from buildKnowledgeProgramFromBusiness().  Links to the Knowledge page
  for full editing.  Prompt chip: "Update tone or goals".

apps/dashboard/src/components/console/panels/HandoffPanel.tsx
  Displays the handoff online/offline status badge and the list of contact methods
  with enabled/disabled state and type icons (phone, email, sms, link, form).
  Prompt chips: "Add a contact" and "Set my status".

apps/dashboard/src/components/console/panels/RecentConversationsPanel.tsx
  Fetches up to the 5 most-recent chat sessions for the active location and
  renders them with status badges (escalated / resolved / open).  Includes
  skeleton loading rows and an empty-state prompt linking to the Widget page.

apps/dashboard/src/components/console/WidgetPreviewColumn.tsx
  Right-column component that embeds the live ChatWidget (initiallyOpen, no
  launcher, no history hydration) alongside a collapsible install snippet with
  clipboard copy.  Derives config from businessToWidgetConfig() and theme from
  widgetThemeToChatTheme().

## INTENTIONALLY DEFERRED

- BehaviorPanel reads training config from buildKnowledgeProgramFromBusiness()
  which derives from the mock store only.  It does not fetch a live
  knowledge_config record from Supabase.  This matches the mock-first architecture
  in place; a Supabase-backed fetch would require the same pattern used in the
  knowledge page and is out of scope for Pass 4.

- configVersion in the conversation fetch dep array over-invalidates (any AI
  tool confirmation triggers a refetch, not just changes that affect sessions).
  This is intentional: it is cheap, always correct, and avoids per-tool
  invalidation logic.

- Widget preview in WidgetPreviewColumn is constrained to a 380px fixed column.
  On mobile viewports the columns stack vertically, which is correct, but the
  widget height may look cramped.  Widget embed responsiveness is out of scope
  for Pass 4.
