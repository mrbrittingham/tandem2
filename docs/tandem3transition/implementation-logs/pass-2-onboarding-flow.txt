Pass 2 — Staged Onboarding Flow
================================
Branch: tandem3/pass-2-onboarding
Date:   2025

Overview
--------
Replaced the flat 3-field onboarding form with a staged, two-column chatbot-led
experience. The left column is an AI chat thread; the right column shows a
contextual panel that changes as the operator progresses through setup.

-------------

  - OnboardingStage union: business-form | website-url | scanning |
    scan-results | scan-review | manual-setup | handoff | complete

Bug Fix vs Original Onboarding
-------------------------------
The original onboarding page sent businessName to POST /api/locations, which was
ignored — the create_business_location RPC requires an existing business_memberships
row. New users would silently fail. Pass 2 fixes this by calling POST /api/bootstrap
first to create the business entity and membership, then calls POST /api/locations.

API Surface Used
----------------
POST /api/bootstrap              — create business + membership (bootstrap_membership RPC)
POST /api/locations              — create first location (create_business_location RPC)
POST /api/website-import/start   — start website scan (source="onboarding")
GET  /api/website-import/latest  — poll scan progress by runId
POST /api/website-import/:id/apply — apply scan draft to location config
PUT  /api/location-config        — save handoff contact methods or manual knowledge

Lint Notes
----------
The react-hooks/set-state-in-effect rule (added in newer eslint-plugin-react-hooks)
fires when setState is called synchronously at the top of a useEffect body. This
pattern is present throughout the pre-existing codebase (conversations, layout,
overview pages) and is flagged project-wide. In useImportPolling.ts the legitimate
reset-on-runId-change setState calls are suppressed with a targeted eslint-disable
block. The pre-existing violations in other files are unchanged.
